**创业板ETF / 1000ETF 差异归因（重要）**：
这两个标的**改造前就已经拿不到真实数据**（`option_finance_board` 不支持深交所期权看板，返回空表），
会落到 `generate_simulated_history()` 模拟数据分支。该函数使用**无种子的 `random.uniform`**，
因此**每次运行结果都不同**——改造前连续两次运行之间的差异幅度，与改造前后的差异幅度完全同量级。
故这两行差异**与本次改造无关**，是既有的模拟数据随机性问题。

**唯一有意的输出差异**：可用数据源展示行由 `✓ akshare (推荐)` 改为 `✓ data_hub期权接口 (akshare内核，推荐)`。

## 五、遗留观察（不在本次范围，供决策）

1. **`skew_percentile.py` 标的现货价取值字段名错误（既有 bug）**
   `get_akshare_skew()` 中 `underlying.iloc[0].get('标的证券最新价') or underlying.iloc[0].get('最新价')`，
   而 akshare `option_finance_sse_underlying` 的真实列名是 **`当前价`**，两个 key 都取不到 → 恒为 `None` →
   永远落到「用首个合约代码反推行权价 × 2.5」的粗略估算（50ETF 实测估算出 6.625，而真实现货 2.836，偏差 2.3 倍），
   进而影响 ATM 行权价选择与 Skew 数值。**本次按要求保持业务逻辑不变，未修复**；
   data_hub 侧已能提供正确现货价，改一行 key 即可修复，但会改变历史 Skew 序列水平，建议单独评估。

2. **创业板ETF / 1000ETF 长期使用模拟数据**
   `option_finance_board` 不支持深交所期权看板（`易方达创业板ETF期权` / `中证1000ETF期权` 返回空表），
   这两个标的的 Skew 实际是**随机模拟值**并被写入 `skew_history.json`，分位数没有统计意义。
   建议后续在 data_hub 的 `option_board` 增加「深交所看板 → `option_current_day_szse` 构造 T 型报价」分支，
   或干脆在报告中明确标注为「无真实数据 / 模拟」，避免误读。

3. **升贴水链路的 2 处 akshare 直连未收敛**（见 1.1 节说明）。
