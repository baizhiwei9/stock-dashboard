# 房价指数技术预警（house_price_alert）

把 **70 城房价指数**（月度）跑一遍技术分析，命中的信号**汇总成一封带图邮件**发出去。
不是每个报警各发一封。

## 数据与指标

| | 内容 |
|---|---|
| 源 | 东方财富 `RPT_ECONOMY_HOUSE_PRICE`（`data_hub.house.sources.price70` 直连） |
| 覆盖 | **70 城 × 190 个月**（2011-01 ~ 最新月），实测 13300 行 / 27 页 / 7.7 秒 |
| 价格序列 | 用**二手住宅环比连乘**还原的合成价格（该城首月 = 100），**不是元/㎡** |
| 指标 | KDJ(9,3,3)、MACD(12,26,9)、20 月均线（中轨） |

## 触发规则

| 规则 | 含义 | 方向 |
|---|---|---|
| MACD 零轴上穿 / 下破 | 中枢转多 / 转空 | bull / bear |
| KDJ 中轴(50)上穿 / 下破 | 中枢转多 / 转空 | bull / bear |
| 价格上穿 / 下破 MA20 | 中轨突破 | bull / bear |
| KDJ 超买（K>=80 或 J>=100） | 注意回调 | warn |
| KDJ 超卖（K<=20 或 J<=0） | 注意反弹 | watch |
| MACD 金叉 / 死叉 | 附属信息 | bull / bear |

**超买超卖按「新进入区间」触发**，不是「停留在区间」。原因：月度指数在单边下行时 KDJ 会
长期钝化贴在 0 附近，实测 70 城里 62 城处于「超卖区」——若按停留判定，一封邮件会塞 60 条
超卖，等于没预警。

## 为什么统一一封

一次跑完全部城市 × 全部规则，`out/state.json` 按 `city|kind|month|code` 去重，只把**新增**
的信号汇总成一封邮件：

- 没有新增信号 → **不发空邮件**
- 有新增 → 一封邮件 + 一张图（只画有信号的城市，最多 6 个）
- 同一信号在同一月只报一次，月度数据更新后才可能再报

## 用法

```bash
export PYTHONPATH=/path/to/datahub-multi-tier
python3 run.py                 # dry-run：抓数 → 分析 → 出图 → 打印邮件预览，不发送
python3 run.py --send          # 真发（需先配好 SMTP 环境变量）
python3 run.py --no-fetch      # 不抓新数据，用库里现有的
python3 run.py --kind new      # 换成新建商品住宅指数
python3 run.py --force         # 忽略去重，把所有信号都当新的（排查用）
```

邮件环境变量（**凭据只从环境读，不写进仓库**）：

```
SMTP_HOST  SMTP_PORT(默认465)  EMAIL_FROM  EMAIL_TO(逗号分隔)
SMTP_USER  SMTP_PASSWORD  SMTP_SSL(默认开)  SMTP_TLS(默认关)
```

## 产物

- `out/signals.json`：全量分析 + 本轮新增 + 各城指标
- `out/signals.md`：人读摘要（就是邮件正文）
- `out/price_tech.png`：技术分析图（有信号时）
- `out/state.json`：去重状态

## 已知限制（写清楚，别当成 bug）

1. **是指数不是单价**：上游只给同比/环比/定基，没有成交金额 → 算不出元/㎡。`price` 字段是
   合成指数（首月=100），只能看方向与幅度，不能当房价引用。
2. **定基字段为空**：东财该报表 `*_BASE` 返回 null，代码里保留但不当有效值用。
3. **月度、滞后 1 个月**：房价指数按月发布，最新一期通常晚一个月，这是源的节律。
4. **KDJ 钝化**：单边行情里 K 会长期贴 0 或 100，此时"新进入"信号偏少属正常。
5. **零轴/中轴穿越是事件**：只检查最新一期，历史穿越不会补报。
